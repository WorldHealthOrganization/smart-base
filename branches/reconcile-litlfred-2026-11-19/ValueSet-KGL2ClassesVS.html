http://smart.who.int/base/CodeSystem/KGL2Classes  program-indicatorProgram IndicatorDAK component 7. They are different things: this is the DAK's operational measure, and `derivedFrom` is how it points at the normative one. Collapsing them would silently merge a WHO definition with a country's implementation of it.
http://smart.who.int/base/CodeSystem/KGL2Classes  functional-requirementFunctional RequirementDAK component 8, first half. The 41 committed instances use the R5 SGRequirements profile rather than this logical model, so a real instance carries `statement` entries and a userstory extension; both shapes are accommodated and `profile` records which was read.
http://smart.who.int/base/CodeSystem/KGL2Classes  non-functional-requirementNon-Functional RequirementDAK component 8, second half. `requirement 1..1 markdown`, an optional category and classification codings. Kept separate from the functional half because the fields genuinely differ -- a non-functional requirement has no actor and no benefit.
http://smart.who.int/base/CodeSystem/KGL2Classes  requirement-statementRequirement StatementOne numbered, labelled statement inside a requirement, with a conformance verb. A node rather than a property because conformance is queried across a whole DAK -- 'every SHALL in this kit, and what fulfils it' is the question requirements exist to answer. It also carries its own success criteria, so 'what would show this SHALL is met' is answerable per statement rather than per requirement.
http://smart.who.int/base/CodeSystem/KGL2Classes  test-scenarioTest ScenarioDAK component 9. `feature 1..1 uri` to a Gherkin feature file, plus an optional description. The feature file's interior is not modelled: no DAK in this estate ships one yet, so a subgraph for it would have no instance to check it against.
http://smart.who.int/base/CodeSystem/KGL2Classes  external-artifactExternal artefactA DAK file addressed by canonical URL: a BPMN process, a DMN decision table, a FHIR resource, a workbook. Deliberately opaque: it carries an IRI and a kind, and nothing about its interior. The L2-BPMN, L2-DMN and L3 classes that describe a file's interior elaborate this class at the same IRI. Moved here from L1 in 3.0 unchanged: a DAK file is the DAK's material, not WHO content.
